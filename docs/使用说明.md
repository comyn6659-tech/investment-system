# 使用说明

面向股东：这份文档说明本系统怎么问、支持哪些问法、卡片怎么读，以及四种结论分别是什么意思。

**一句话**：系统把「已批准的规则 + 已提交的固定数据」重新算一遍，输出一张固定结构的卡片。
系统内部不调用任何大模型，也没有「我觉得」；所有数字都能从固定快照与政策文件复核。

## 1. 怎么问

### 1.1 在终端

```bash
cd /Users/comyn/Documents/投资/投资分析系统/investment-system
./ask "招商银行怎么样"
```

| 命令 | 作用 |
|---|---|
| `./ask "问题"` | 输出卡片（默认不超过 25 行）；提问前会尝试一次轻量自动更新 |
| `./ask --detail "问题"` | 展开逐条条件、敏感性、近似项、每股净资产等细节 |
| `./ask --json "问题"` | 输出结构化 JSON（给程序或留档用） |
| `./ask --no-update "问题"` | 不联网更新，直接用已提交的行情快照（离线可用） |
| `./ask --analysis-date 2026-11-14 "问题"` | 指定分析日复现（维护、复核用） |
| `./ask --recompute <record_id>` | 按账本记录引用的快照与政策复算并逐项对比（只读；0=一致、1=不一致、2=不可复算） |
| `./web` | 打开本机页面（只监听 127.0.0.1）：提问、买点总览、三个池、指数、账本、数据状态 |

第一次使用前确认 Python 环境存在：`.venv/bin/python --version`（本项目用 Python 3.12）。
命令报错时，系统会打印「查询失败」和真实原因，不会编一个答案。

### 1.2 在本地页面（`./web`）

```bash
./web                 # 打开 http://127.0.0.1:8765/（端口被占用时自动换端口），自动在浏览器打开
./web --no-browser    # 不自动打开浏览器（服务器地址会打印在终端）
./web --no-update     # 与 ./ask --no-update 一致：不尝试联网更新
```

- 页面**只监听本机** 127.0.0.1，不访问外网、不上传任何数据；关闭终端即停止。
- 页面上的数字与结论都来自 `./ask` 同一套引擎：同一个问题，卡片文字与终端逐字一致；
  页面不额外计算任何估值或结论。
- 页面写账本规则与 `./ask` 完全相同：正式结论只追加、同一标的/同一分析日/同一快照重复运行内容一致则跳过。
- 六个部分：提问；买点总览（候选买点与「离买点最近」排行，按类型分组，可按池/行业/所有制筛选）；
  三个池（可搜索、排序、筛选行业/所有制/周期，点公司看卡片与成绩单）；指数（位置说明 + 近 5 年分位走势图）；
  账本（按公司查、显示改判记录、任一条可点「复算」）；数据状态（行情日期、上次自动更新时间与结果、下一次复核日期）。

### 1.3 在 Claude Code / 其他 AI 助手

根目录的 `CLAUDE.md` 与 `SKILL.md` 是给 Claude 的硬性规则：遇到投资问题时必须先运行
`./ask "<原问题>"`，然后把输出**逐字原样**呈现（包括结论、数字、日期、来源、免责声明）。
不允许改写、补充买卖意见、给目标价，也不允许用模型自己的知识替代卡片。

### 1.4 每日自动更新（可选，需手动安装一次）

```bash
scripts/install-daily-update.sh --dry-run   # 先看会写什么
scripts/install-daily-update.sh             # 安装（macOS launchd，每日 18:30）
scripts/uninstall-daily-update.sh           # 卸载
```

安装后每天自动运行 `./update`，把新行情、新周度信号、官方估值等**只追加**到账本；
失败不影响查询，卡片会注明数据日期。详见《维护说明》。

## 2. 支持的问法

| 你问什么 | 例子 | 卡片给什么 |
|---|---|---|
| 单只个股 | 「茅台怎么样」「600519 贵不贵」「美的能买吗」 | 四种结论之一 + 现价、候选门槛、三档价值、起约束条件、等级含义、局限、来源 |
| 银行 | 「招商银行怎么样」「平安银行怎么样」 | 银行池 11 家给正式结论；非银行池银行只给价值数字 + 未通过条件，结论固定「无法判断」 |
| 宽基指数 | 「沪深300 现在什么位置」「中证500 贵不贵」「中证1000 什么位置」 | 近 5 年估值位置分档 + 候选 A 研究信号（未批准，只作研究记录） |
| 恒生科技 | 「恒生科技」 | 官方月度 PE/股息率快照 + 无历史分位的如实说明 |
| ETF | 「510300 能买吗」「510500 怎么样」 | 产品资料检查 + 跟踪指数的位置研究信号；**不做执行检查、不给买卖判断** |
| 池名单 | 「好公司池有哪些」「收息池里的国企」「银行池」 | 三池名单、规则版本、快照日期；入池 ≠ 买入 |
| 是否在池 | 「格力在不在好公司池」「为什么比亚迪不在」 | 在/不在 + 未通过的条件与数值；范围外会说明原因 |
| 排行 | 「好公司里谁离买点最近」「现在有哪些候选买点」「银行池里谁离买点最近」 | 按现价距候选门槛排序，只排状态完整、等级 A/B 的正式结论 |
| 历史 | 「茅台以前的结论」 | 只追加账本中的历史记录与改判记录 |
| 状态 | 「数据是哪天的」「规则什么时候复核」 | 数据日期、行情日期、政策版本与复核日 |
| 范围外 / 歧义 | 「创业板」「中国平安」「苹果公司」「159915」 | 如实说明不在范围或需要确认；不猜 |

不支持的问题会明确说「系统目前不支持这个问法」，并提示可用问法。
如果问题像是在问一家公司、但名字认不出来，卡片会直接说
「没找到叫『X』的上市公司，请用证券简称或 6 位代码」。

## 3. 卡片怎么读

下面是一张真实的银行卡片（2026-11-14 实际输出）：

```markdown
类型：银行池｜按银行专用标准
提示：系统不判断护城河是否仍然存在，请自行研究其生意。

**结论：候选买点** — 现价不高于门槛价，也不高于悲观价值。

现价 42.93 元（2026-11-13）｜门槛 46.41 元｜距门槛 -7.5%
正式结论（银行专用估值政策，已批准 2026-11-14）
关键指标：市净率 0.92 倍｜股息率 4.7%｜不良率 0.94%｜拨备覆盖率 389.39%｜核心一级 14.39%
市净率口径：普通股口径 = 价格 ÷ 每股净资产；每股净资产 =（归母净资产 − 其他权益工具）÷ 股本（与银行 v2.1 估值同口径）。
三档价值（元/股）：悲观 46.41（最悲观假设下每股值多少）｜基准 67.84（安全边际的计算基准）｜乐观 77.34（高于它就判回避）
为什么：起约束条件 悲观价值；现价不高于门槛价，也不高于悲观价值。
三档净资产收益率：基准 13.4%（假设停在最近一年）｜悲观 9.8%（再按近 3 年速度下滑 3 年）｜乐观 14.7%（近 3 年平均）
历史位置：市净率处于近 10 年 21% 分位，股息率处于 68% 分位（历史分位用东方财富市场市净率与分红数据，可用 106 个月月末序列；市场市净率与卡片普通股口径可能略有差异，未做换算，只作描述，不给买点）。
隐含长期回报率：约 14.5%（假设净资产收益率保持最新水平、按现价买入；描述性，不参与结论）。
它是什么：银行池成员｜所有制 央企｜周期属性 非周期（银行）｜等级 B（银行池最高等级）
局限：净资产收益率仍在下滑；报表坏账可能低估；只能前向验证。
来源与日期：行情 腾讯财经（2026-11-13）；财务 东方财富 2025 年报 / 2026 三季报；银行专用估值政策（已批准 2026-11-14，复核 2027-05-31）。
不构成投资建议。
```

逐行读法：

| 行 | 含义 |
|---|---|
| 第一行「类型」 | 个股与银行卡片的第一行：按已批准三池名单标注它属于哪一类（好公司型 / 好公司型＋收息型 / 收息型 / 银行池 / 池外），不参与估值与结论 |
| 第二行「提示」 | 固定提示：系统不判断护城河是否仍然存在，请自行研究其生意 |
| 「结论」 | 四种结论之一 + 一句话原因；这是卡片唯一的买卖判断，后面都是解释 |
| 现价 / 门槛 / 距门槛 | 现价来自行情快照，括号内是价格日期；门槛是规则算出的候选买点价；距门槛为负表示现价已低于门槛 |
| 正式结论 / 研究 / 预演 | 「正式结论」= 已批准政策的正式输出；「研究」「预演」「未批准」= 只作研究参考，不构成买卖结论 |
| 关键指标 | 市净率、股息率、不良率、拨备覆盖率、核心一级资本充足率 |
| 市净率口径 | 普通股口径（价格 ÷ 每股净资产，每股净资产 =（归母净资产 − 其他权益工具）÷ 股本） |
| 三档价值 | 悲观（最悲观假设下每股值多少）/ 基准（安全边际的计算基准）/ 乐观（高于它就判回避）；注意括号里的用途 |
| 为什么 | 起约束条件（哪一条约束了当前结论）与未满足条件 |
| 三档净资产收益率 / 其他指标 | 结论背后的关键假设；描述性指标会注明「不参与结论」 |
| 历史位置 / 隐含长期回报率 | 只作描述，不是买点；历史分位口径以行内说明为准 |
| 它是什么 / 等级 | 所属池、所有制、周期属性；A/B/C 衡量数据完整度与模型稳定性，**不是公司质量** |
| 局限 / 来源与日期 | 已知局限、数据来源与日期、政策版本与复核日 |
| 不构成投资建议 | 固定免责声明，任何卡片都有 |

个股卡片（非银行）结构类似，但没有三档净资产收益率与历史位置，会注明政策版本
`equity-policy-v1.1`（已批准 2026-11-12，复核 2027-05-31）。

### 3.1 五种类型（个股与银行卡片第一行）

| 类型 | 条件（只看已批准名单） | 一句话含义 |
|---|---|---|
| 好公司型 | 在好公司池 | 过去十年持续高回报，有护城河的财务脚印（系统不能验证护城河本身） |
| 好公司型＋收息型 | 同时在好公司池与稳定收息池 | 同上，并且利润稳、分红稳 |
| 收息型 | 只在稳定收息池 | 利润稳、分红稳；没有持续高回报，买点主要来自「便宜＋分红」 |
| 银行池 | 在银行池（按银行专用估值） | 按银行专用标准 |
| 池外 | 不在任何池（含券商保险、ST、上市不满 7 年等未通过或未参与筛选的公司） | 未通过或未参与筛选；结论只按估值规则，质量未经筛选 |

类型只是「按哪个名单与标准看它」，不改变任何结论：同一个问题，类型行只影响你怎么读这张卡片。
排行与「现在有哪些候选买点」按同样五种类型分组显示，组内仍按现价距门槛排序。

## 4. 四种结论的含义

| 结论 | 规则（已批准政策） | 读法 |
|---|---|---|
| **候选买点** | 等级 A/B、状态完整，且现价 ≤ 候选门槛、现价 ≤ 悲观价值。个股门槛 = 基准价值 ×（1 − 安全边际）；A 级安全边际 25%，B 级 40%。银行门槛 = min（基准价值 ×（1 − 30%）, 悲观价值） | 按本系统规则，现价同时低于门槛与悲观价值；不等于「一定涨」 |
| **等待** | A/B 级、状态完整，但不是候选买点、也不是回避 | 价格还不够低；等价格变化或下次更新 |
| **回避** | A/B 级、状态完整，且现价 > 乐观价值 | 仅说明现价高于乐观情景价值，**不是对公司质量的负面判断** |
| **无法判断** | 等级 C、资料不足、路线不支持（保险/券商/强周期/困境）、不在银行池、指数/ETF 研究信号、范围外等 | 系统不下结论；卡片会写明原因。不要自行补一个结论 |

补充：

- **入池 ≠ 买入**。三池只回答「过去十年用公开数据看是不是好公司」，不回答「现在便不便宜」。
- **指数与 ETF 没有正式买点**。指数只展示估值画像与候选 A 研究信号（未批准）；ETF 只做产品资料检查。
- **银行只有银行池 11 家给正式结论**；其他银行只给三档价值与「无法判断」，并列出未通过的银行池条件。
- **安全边际与门槛是规则值，不是目标价**；系统不预测股价，也不给仓位建议。

## 5. 常见问题

- **卡片里的数据是哪天的？** 卡片「来源与日期」行会写行情日期、财务期与政策版本。`./ask "数据是哪天的"` 可查当前数据日期。
- **为什么同一只股票今天的结论和昨天不一样？** 行情价格变了，或自动更新了新一期财务/估值；规则本身不变。规则只在股东批准后才改。
- **为什么系统说「无法判断」？** 卡片第二句会写原因（等级 C / 资料不足 / 路线不支持 / 不在银行池 / 范围外等）。
- **可以问「多少钱买」「能涨多少」「仓位多少」吗？** 系统只按规则给候选门槛与三档价值，不预测股价、不给目标价和仓位。
- **页面怎么打开？** 在仓库根目录运行 `./web`，浏览器会打开本机页面；关闭终端即停止。
  页面上的卡片与 `./ask` 逐字一致，账本规则也相同。
- **为什么卡片第一行是「类型」而不是结论？** 系统先说明这只股票按哪个名单与标准看，再给结论；
  类型不参与估值，结论仍是已批准政策算出来的四种之一。
- **结果在哪里留痕？** 正式结论写入只追加账本 `data/ledger/equity-conclusions.jsonl`；
  每条新记录带所用财务快照、行情快照与政策文件的哈希。用 `./ask --recompute <record_id>`
  可按记录引用的快照与政策重算并逐项对比（只读，不改账本）；旧记录中无法复算的清单见《维护说明》§7。
