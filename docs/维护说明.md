# 维护说明

面向股东与接手人：这份文档说明系统的日常维护、定期更新、年度重跑、结论账本复盘与出错处理。
所有命令都在仓库根目录执行：`cd /Users/comyn/Documents/deepseek-harness/投资/investment-system`。

> 三条铁律：
> 1. **不手工改账本**（`data/ledger/*.jsonl` 只追加；改一行就会校验失败）。
> 2. **不手工改已批准政策与已提交快照**（改了哈希就变；规则修改必须重新批准）。
> 3. **验证优先**：任何维护操作后跑一遍《5. 校验清单》，确认行为与账本没变。

## 1. 每日自动更新（行情 + 前向记录）

### 1.1 一次性安装（需股东手动执行）

```bash
scripts/install-daily-update.sh --dry-run   # 先看会写入的 plist 与命令
scripts/install-daily-update.sh             # macOS launchd，每日 18:30
scripts/uninstall-daily-update.sh           # 卸载
```

- 定时任务只支持 macOS（launchd）；运行时代码不会自动安装。
- 日志：`data/logs/daily-update.log`、`data/logs/daily-update.err.log`（不入 git）。
- 手动执行一次：`./update`（或 `.venv/bin/python tools/update.py`）。
- 只做本地/离线部分：`.venv/bin/python tools/update.py --skip-network`。

### 1.2 `update` 做什么

依次尝试：官方日频序列（中证指数，沪深300/中证500/中证1000）→ 候选 A 周度信号 →
全市场行情（腾讯财经，5,225 只 A 股）→ 官方当日估值 → 恒生科技官方月度估值。
每一步都是**只追加 / 重复跳过 / 冲突不覆盖**；单步失败不阻断其他步骤；每次运行写一条
`data/ledger/update-log.jsonl`。运行状态：`./update --check`（各账本完整性）。

`./ask` 每次提问前会尝试一次轻量更新（不刷新官方长序列）；当天已成功则跳过。离线或更新失败
不影响查询，卡片会注明数据日期；需要完全离线时用 `./ask --no-update "问题"`。

### 1.3 更新后检查

```bash
./update --check
.venv/bin/python -m engine.cli --check-conclusions
```

## 2. 年度重跑三池（每年一次；下次 2027-11-13 前）

三套池规则已批准（决策③），每年按同一规则重建快照并重跑，追加池账本；**不改任何阈值**。

```bash
.venv/bin/python tools/run_annual_pools.py --dry-run   # 只打印步骤，建议先跑
.venv/bin/python tools/run_annual_pools.py             # 实际执行（联网）
```

命令顺序：

1. `tools/build_quality_pool_data.py` 重建好公司池快照；
2. `tools/run_quality_pool.py` 按已批准规则重跑、追加好公司池账本；
3. `tools/build_income_pool_data.py --build-tables --build-snapshot` 重建收息池快照；
4. `tools/run_income_pool.py` 重跑、追加收息池账本；
5. `tools/build_bank_pool_data.py --build-tables --build-snapshot` 重建银行池快照；
6. `tools/run_bank_pool.py` 重跑、追加银行池账本。

注意：

- 重跑会生成**新快照目录**并更新 `data/*/manifest.json` 的 `current`；旧快照不删除
  （历史账本仍引用它们，删除会让历史记录悬空）。
- 如果只是想校验当前名单而不重跑：`tools/run_quality_pool.py --check`（收息池/银行池同理）。
- 重跑后如名单变化，先看 `docs/archive/phase4*` 的判读方式，再决定是否向股东报告；
  不因入池数量调整阈值。

## 4. 2027-05-31 结论账本复盘（首次）

目标：用真实前向记录检验「规则是否值得继续用」，而不是按短期结果改参数。

### 4.1 步骤

1. **冻结数据与账本**：先确认 `git status` 干净，记下当前 HEAD；本轮复盘只读。
2. **完整性校验**：

   ```bash

   .venv/bin/python tools/update.py --check
   .venv/bin/python tools/run_quality_pool.py --check
   .venv/bin/python tools/run_income_pool.py --check
   .venv/bin/python tools/run_bank_pool.py --check
   .venv/bin/python scripts/verify-ledger-snapshots.py
   ```

3. **汇总统计**（只读脚本，可按需保存输出）：

   ```bash
   .venv/bin/python - <<'EOF'
   import json
   from collections import Counter
   rows = [json.loads(l) for l in open('data/ledger/equity-conclusions.jsonl', encoding='utf-8') if l.strip()]
   print('总记录', len(rows))
   print('按记录类型/结论', dict(Counter((r.get('record_type') or 'formal') + ':' + str(r.get('conclusion')) for r in rows)))
   print('按分析日', dict(Counter(r.get('analysis_date') for r in rows)))
   print('改判记录', [(r.get('analysis_date'), r.get('code'), r.get('reversal_of')) for r in rows if r.get('record_type') == 'reversal'])
   EOF
   ```

4. **逐条复盘**：对每条正式结论核对——当时的规则与输入是否与账本一致；之后价格是否触及
   门槛/乐观价值；结论与后续事实是否明显背离；改判记录的原因是否成立；有没有数据缺失导致的
   无法判断。银行 11 家单独一组（v2.1 首次记录 2026-11-14）。
5. **判断规则是否需要改**：默认不改；若确有规则缺陷，写清证据、影响面与修订草案，先跑测试，
   再提请股东批准。**不因某只股票赚钱/亏钱改规则。**
6. **输出复盘报告**：写入 `docs/archive/phase5-review-2027-05.md`（或按内部约定命名），
   内容包括统计、逐条核对结论、发现的问题与建议、下一复核日。
7. **更新复核日**：政策 `approval.review_date` / `next_review_date` 按批准结果更新，
   记录在案；账本不回溯。

### 4.2 银行 v2.1 复核重点

## 7. 正式结论复算（`--recompute`）

### 7.1 新记录带追溯字段

新写入的正式结论（个股与银行）在账本记录中带 `trace`：

| 字段 | 内容 |
|---|---|
| `trace.policy` | 政策文件路径 + sha256 |
| `trace.financial` | 批量财务快照（`qps-…` + manifest 哈希），或单标的快照文件（id+sha256），或银行估值输入（inputs/history 哈希） |
| `trace.quote` | 行情快照 id、精确路径 + sha256、价格日期（或快照内的价格事实） |

`price_date` 同时写在记录顶层。覆盖写入路径：`engine/cli.py`（个股/银行）、
`engine/ask/service.py`、`engine/policy/conclusion.py`、`engine/bank/conclusion.py`、
`tools/run_equity_conclusions.py`、`tools/run_pool_valuation.py`、`tools/write_bank_conclusions.py`。
引用的快照均为已提交文件或每日更新保留文件（不被 git 忽略）。

### 7.2 命令

```bash
./ask --recompute <record_id>                  # 用仓库账本
./ask --recompute <record_id> --ledger <path>  # 指定账本（沙箱/临时目录）
```

- 退出码：`0` 一致；`1` 不一致（打印逐项差异）；`2` 不可复算或找不到记录。
- 逐项对比 `price`、`price_date`、`values.pessimistic/base/optimistic`、`grade`、
  `margin_of_safety`、`conclusion`、`binding_condition`；数值相对差阈值 **1e-9**。
- 命令只读，不写任何账本；校验引用的政策/快照/行情文件哈希后才重算。

## 9. 出错怎么办

| 现象 | 先做什么 | 不要做什么 |
|---|---|---|
| `./ask` 报「查询失败」 | 用 `./ask --no-update "问题"` 重试；仍失败看错误类型与数据日期 | 不要自己编答案，不要手工改数据 |
| 卡片数据日期很旧 / 更新失败 | 看 `data/logs/daily-update.log`、`data/ledger/update-log.jsonl`；手动 `./update` 重试 | 不要删账本「重来」 |
| 自动更新某一步失败 | 单步失败不阻断其他步骤；重跑即可（幂等、重叠跳过） | 不要用冲突内容覆盖已有快照/账本 |
| 快照校验失败（`SnapshotError`） | `git status` 看是否被本地改动；用 `git checkout -- <路径>` 恢复；或从 git 历史重新检出 | 不要手工改 `*.csv.gz.meta.json` 或无清单重建 |
| 账本 `--check` 报错 | 立即停下，检查是否被手工编辑/重复运行产生不同内容；用 git 恢复被误改的行 | 不要直接删行、改 `record_id` 或覆盖文件 |
| 定时任务不触发 | 看 `~/Library/LaunchAgents/com.investment-system.forward-update.plist` 与日志；重新执行安装脚本 | 不要用 `pkill -f` 之类宽匹配杀进程 |
| 磁盘紧张 | 可安全删除 git 忽略缓存：`data/cache/`（保留 `.gitkeep`）、`data/policy-trial/cache/`、`data/policy-trial/logs/`、`.pytest_cache/`、`__pycache__/`；**不要删 `data/snapshots/`、`data/*/snapshot-*`、账本、政策** | 不要删 `.venv`/`.git`，不要删历史快照 |
| 需要回滚代码 | `git log` 找到上一签收提交，`git revert` 或 `git checkout` 到干净状态 | 不要 `git reset --hard` 抹掉别人提交；不 amend 已推送历史 |
| 需要恢复数据文件 | `git checkout -- <路径>`；历史快照与账本都在 git 里 | 不要从旧项目 `../valuation/` 读取或导入 |

## 10. 数据与缓存约定

- 运行时只读**已提交**的数据：快照、政策、账本、注册表；不读被 git 忽略的缓存
  （由 `tests/test_clean_inputs.py` 扫描保证）。
- `data/cache/`、`data/policy-trial/cache/`、`data/policy-trial/logs/`、`data/logs/` 都是可删除缓存/日志；
  删除后首次联网运行会重新采集。
- 快照目录（`data/*/snapshot-*`）与账本**不可手改**；任何变化都要能被快照清单与账本哈希检出。
- `.venv/` 是本机 Python 环境，不入 git；重建方式：`python3.12 -m venv .venv` 后按
  `requirements-data.txt` 安装依赖。
