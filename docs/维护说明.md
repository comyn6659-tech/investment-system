# 维护说明

面向股东与接手人：这份文档说明系统的日常维护、定期更新、年度重跑、结论账本复盘与出错处理。
所有命令都在仓库根目录（`investment-system/`）执行。

> 三条铁律：
> 1. **不手工改账本**（`data/ledger/*.jsonl` 只追加；改一行就会校验失败）。
> 2. **不手工改已批准政策与已提交快照**（改了哈希就变；规则修改必须重新批准）。
> 3. **验证优先**：任何维护操作后跑一遍《5. 校验清单》，确认行为与账本没变。

## 1. 每日自动更新（行情 + 前向记录）

### 1.1 一次性安装（需股东手动执行）

```bash
scripts/install-daily-update.sh --dry-run   # 先看会写入的 plist 与命令
scripts/install-daily-update.sh             # macOS launchd，每日 18:30
scripts/uninstall-daily-update.sh           # 卸载
```

- 定时任务只支持 macOS（launchd）；运行时代码不会自动安装。安装完成后脚本会打印 plist
  实际路径、解释器、`tools/update.py` 与工作目录，便于核对。
- 自检：`./update --check` 会读取
  `~/Library/LaunchAgents/com.investment-system.forward-update.plist`；plist 不存在，或其中
  `WorkingDirectory`、`ProgramArguments`、日志路径不是当前项目路径时，明确报错并给出修复命令
  （重新执行 `scripts/install-daily-update.sh`）。项目搬目录后必须先重装一次。
- 日志：`data/logs/daily-update.log`、`data/logs/daily-update.err.log`（不入 git）。
- 手动执行一次：`./update`（或 `.venv/bin/python tools/update.py`）。
- 只做本地/离线部分：`.venv/bin/python tools/update.py --skip-network`。

### 1.2 `update` 做什么

依次尝试：官方日频序列（中证指数，沪深300/中证500/中证1000）→ 候选 A 周度信号 →
全市场行情（腾讯财经，5,225 只 A 股）→ 官方当日估值 → 恒生科技官方月度估值 →
**财报季批量快照（仅到期日）→ 红线周度扫描（每周首次）→ 结论变化（只写改变的）**。
每一步都是**只追加 / 重复跳过 / 冲突不覆盖**；单步失败不阻断其他步骤；每次运行写一条
`data/ledger/update-log.jsonl`。运行状态：`./update --check`（各账本完整性 + 定时任务路径自检）。

行情日期**逐行**按腾讯返回的行情时间戳判断，不用系统时间硬套：
行情日早于今天时「当前价」就是该日收盘；行情日等于今天且未到 15:00 取昨收；15:00 后取当日收盘。
因此周二凌晨、盘中、收盘后、周末与节假日后开盘前都会得到同一个「最近已完成交易日」，
不会把更早的收盘价标成新日期，也不会反复与已有快照冲突。

监测三步只在**完整每日更新**执行：`./ask` 提问前的轻量更新与 `--skip-network` 不跑。

`./ask` 每次提问前会尝试一次轻量更新（不刷新官方长序列）；当天已成功则跳过。离线或更新失败
不影响查询，卡片会注明数据日期；需要完全离线时用 `./ask --no-update "问题"`。

### 1.3 更新后检查

```bash
./update --check                                  # 账本 + 定时任务 plist 路径
.venv/bin/python -m engine.cli --check-conclusions
.venv/bin/python tools/run_monitoring.py check
```

`./update --check` 若报 `定时任务 plist 不存在` 或 `WorkingDirectory 指向旧路径`，按输出的
`修复：` 命令重装后再跑。

### 1.4 持续监测（红线、财报季、变动提醒）

规则见《规则说明》§3.6–3.7；政策文件 `data/policies/pool-monitoring-v1.json`（决策⑤，2026-11-17）。
**不新增定时安装**：跟着已安装的每日 18:30 `./update` 跑。

| 任务 | 时机 | 做什么 | 记录 |
|---|---|---|---|
| 红线周度扫描 | 每周首次每日更新 | 三池全部成员逐家查公告（立案/行政处罚/公开谴责/纪律处分）、最近 5 个财年审计意见、控股股东（或第一大股东）质押比例；命中即从全部池剔除 | `data/ledger/{quality,income,bank}-pool.jsonl` 追加 `record_type=exclusion`；`monitoring-scans.jsonl`；`changes.jsonl` |
| 财报季更新 | 5/5、9/5、11/5 之后首次更新 | 按报告期抓取新财报，生成新批量快照（旧快照保留），切换 `data/pool-valuation/manifest.json` 的 `current`；同时刷新银行 v2.1 输入表（`inputs-<报告期>.csv.gz`） | `changes.jsonl`；旧快照与旧输入表保留 |
| 结论变化 | 财报/价格更新后 | 重跑已有正式结论的公司；只有结论改变才追加（含改判为无法判断） | 结论账本 + `changes.jsonl` |
| 变动提醒 | 上述动作后 | 页面「数据状态 → 最近变动」与 `./ask "最近有什么变动"`；出池/候选买点新增消失发 macOS 通知 | `changes.jsonl`（只追加，至少 1 年） |

手动命令：

```bash
.venv/bin/python tools/run_monitoring.py scan              # 立即扫描一次（联网，约 3–5 分钟）
.venv/bin/python tools/run_monitoring.py scan --dry-run    # 只算不写，先看覆盖率与命中
.venv/bin/python tools/run_monitoring.py status            # 最近扫描、覆盖率、出池、变动
.venv/bin/python tools/run_monitoring.py check             # 扫描/出池记录结构检查
```

- 扫描结果按 ISO 周去重；同一周已扫描不会重复跑。取数失败记「本周未完成」，不默认通过、
  也不剔除，下周重试。扫描不落盘缓存：每次直接取公开接口，失败就如实记未完成；生产代码
  不读 `data/cache/monitoring/`，该目录（若存在）可直接删除，删除不影响扫描。
- 公告判定与建池共用 `engine/monitoring/classify.py`；已提交建池快照或人工核对过的事件按
  `art_code` 沿用原判定，不重新判。正文取不到、或正文无法同时确定主体与事项时记「待定」，
  计入「本周未完成」，不得当成通过，也不得触发剔除。
- 扫描记录（`monitoring-scans.jsonl`）逐家写证据：质押比例/主体/截至日/来源、审计意见
  年份→意见/来源、公告源（eastmoney/sina/已提交）、检索区间、事件列表及是否计入与理由。
- 质押红线每周实查：即使已提交表比例为 0，也请求重要股东质押明细；基准日为已提交表
  report_date（缺失用池快照取数日），基准日后无新公告才沿用旧比例，有新公告按最新累计
  质押股数 ÷ 持股数重算。明细请求本次扫描重试 3 次仍失败 → 本周未完成，不用旧数据补成
  通过；扫描记录写 `live_checked`、基准日与新公告条数，汇总报告 live_checked 家数。
- 出池只追加，不改旧记录；已出池公司不在年中回池，回池只在年度重跑时按全部条件重新判定。
- 财报季没有到期日时三步都跳过；`--dry-run` 只算不写。

## 2. 年度重跑三池（每年一次；下次 2027-11-13 前）

三套池规则已批准（决策③），每年按同一规则重建快照并重跑，追加池账本；**不改任何阈值**。

```bash
.venv/bin/python tools/run_annual_pools.py --dry-run   # 只打印步骤，建议先跑
.venv/bin/python tools/run_annual_pools.py             # 实际执行（联网）
```

命令顺序：

1. `tools/build_quality_pool_data.py` 重建好公司池快照；
2. `tools/run_quality_pool.py` 按已批准规则重跑、追加好公司池账本；
3. `tools/build_income_pool_data.py --build-tables --build-snapshot` 重建收息池快照；
4. `tools/run_income_pool.py` 重跑、追加收息池账本；
5. `tools/build_bank_pool_data.py --build-tables --build-snapshot` 重建银行池快照；
6. `tools/run_bank_pool.py` 重跑、追加银行池账本。

注意：

- 重跑会生成**新快照目录**并更新 `data/*/manifest.json` 的 `current`；旧快照不删除
  （历史账本仍引用它们，删除会让历史记录悬空）。
- 如果只是想校验当前名单而不重跑：`tools/run_quality_pool.py --check`（收息池/银行池同理）。
- 重跑后如名单变化，先看 `docs/archive/phase4*` 的判读方式，再决定是否向股东报告；
  不因入池数量调整阈值。

## 3. 每半年更新无风险利率与股权风险溢价（下一次 2027-05）

政策规定：无风险利率随中债 10 年期收益率数据刷新；ERP 每半年随 Damodaran 最新版本更新。

### 3.1 无风险利率（数据刷新，不改规则）

```bash
.venv/bin/python tools/build_policy_trial_data.py --macro-only --as-of 2027-05-31
```

- 该命令联网采集 10 年期国债收益率历史，写入 `data/policy-trial/macro/cn-10y-yield.json`，
  并更新内容哈希；规则仍是「max(最新值, 近 120 个月月末均值)」，不改公式。
- 校验：`./ask "数据是哪天的"` 与卡片来源行显示的日期；必要时用
  `./ask --no-update "招商银行怎么样"` 抽查折扣率是否变化（银行卡片不直接显示 k，
  可在 `--detail` 中查看）。

### 3.2 股权风险溢价（若数值变化，属于政策参数变更）

1. 查 Damodaran「Country Default Spreads and Risk Premiums」最新中国总股权风险溢价；
2. 若与当前 5.14% 不同：先改**草案** `data/policies/equity-policy-v1.1-draft.json`
   的 `discount_rate.equity_risk_premium`（含 `as_of` 与 `basis`），跑全量测试；
3. 生成影响说明（哪些结论会变、账本只追加），**提请股东批准**；
4. 批准后同步 approved 文件（`equity-policy-v1.1.json`）、版本号/批准记录、复核日，
   再重跑并追加账本。**不得只改 approved 文件、不做批准记录**。
5. 银行 v2.1 的 k = 无风险利率 + ERP + 银行溢价，随同一数据自动变化；银行政策参数不变。

> 规则修改后，旧账本记录不回溯、不改写；新记录带新的 `policy_version` / `policy_digest`。

## 4. 2027-05-31 结论账本复盘（首次）

目标：用真实前向记录检验「规则是否值得继续用」，而不是按短期结果改参数。

### 4.1 步骤

1. **冻结数据与账本**：先确认 `git status` 干净，记下当前 HEAD；本轮复盘只读。
2. **完整性校验**：

   ```bash
   .venv/bin/python -m engine.cli --check-conclusions
   .venv/bin/python tools/update.py --check
   .venv/bin/python tools/run_quality_pool.py --check
   .venv/bin/python tools/run_income_pool.py --check
   .venv/bin/python tools/run_bank_pool.py --check
   .venv/bin/python scripts/verify-ledger-snapshots.py
   ```

3. **汇总统计**（只读脚本，可按需保存输出）：

   ```bash
   .venv/bin/python - <<'EOF'
   import json
   from collections import Counter
   rows = [json.loads(l) for l in open('data/ledger/equity-conclusions.jsonl', encoding='utf-8') if l.strip()]
   print('总记录', len(rows))
   print('按记录类型/结论', dict(Counter((r.get('record_type') or 'formal') + ':' + str(r.get('conclusion')) for r in rows)))
   print('按分析日', dict(Counter(r.get('analysis_date') for r in rows)))
   print('改判记录', [(r.get('analysis_date'), r.get('code'), r.get('reversal_of')) for r in rows if r.get('record_type') == 'reversal'])
   EOF
   ```

4. **逐条复盘**：对每条正式结论核对——当时的规则与输入是否与账本一致；之后价格是否触及
   买点线/乐观价值；结论与后续事实是否明显背离；改判记录的原因是否成立；有没有数据缺失导致的
   无法判断。银行 11 家单独一组（v2.1 首次记录 2026-11-14）。
5. **判断规则是否需要改**：默认不改；若确有规则缺陷，写清证据、影响面与修订草案，先跑测试，
   再提请股东批准。**不因某只股票赚钱/亏钱改规则。**
6. **输出复盘报告**：写入 `docs/archive/phase5-review-2027-05.md`（或按内部约定命名），
   内容包括统计、逐条核对结论、发现的问题与建议、下一复核日。
7. **更新复核日**：政策 `approval.review_date` / `next_review_date` 按批准结果更新，
   记录在案；账本不回溯。

### 4.2 银行 v2.1 复核重点

- ROE 是否继续下滑、是否超出悲观假设（近 3 年速度外推 3 年）；
- 报表不良率与拨备是否出现恶化证据，是否触发资产质量扣减；
- 11 家的结论分布（候选买点/等待/回避/无法判断）与价格距离；
- 若证据恶化，按改判规则追加「无法判断」记录，不改旧记录、不改参数。

## 7. 正式结论复算（`--recompute`）

### 7.1 新记录带追溯字段

新写入的正式结论（个股与银行）在账本记录中带 `trace`：

| 字段 | 内容 |
|---|---|
| `trace.policy` | 政策文件路径 + sha256 |
| `trace.financial` | 批量财务快照（`qps-…` + manifest 哈希），或单标的快照文件（id+sha256），或银行估值输入（inputs/history 哈希） |
| `trace.quote` | 行情快照 id、精确路径 + sha256、价格日期（或快照内的价格事实） |

`price_date` 同时写在记录顶层。覆盖写入路径：`engine/cli.py`（个股/银行）、
`engine/ask/service.py`、`engine/policy/conclusion.py`、`engine/bank/conclusion.py`、
`tools/run_equity_conclusions.py`、`tools/run_pool_valuation.py`、`tools/write_bank_conclusions.py`。
引用的快照均为已提交文件或每日更新保留文件（不被 git 忽略）。

### 7.2 命令

```bash
./ask --recompute <record_id>                  # 用仓库账本
./ask --recompute <record_id> --ledger <path>  # 指定账本（沙箱/临时目录）
```

- 退出码：`0` 一致；`1` 不一致（打印逐项差异）；`2` 不可复算或找不到记录。
- 逐项对比 `price`、`price_date`、`values.pessimistic/base/optimistic`、`grade`、
  `margin_of_safety`、`conclusion`、`binding_condition`；数值相对差阈值 **1e-9**。

## 9. 出错怎么办

| 现象 | 先做什么 | 不要做什么 |
|---|---|---|
| `./ask` 报「查询失败」 | 用 `./ask --no-update "问题"` 重试；仍失败看错误类型与数据日期 | 不要自己编答案，不要手工改数据 |
| 卡片数据日期很旧 / 更新失败 | 看 `data/logs/daily-update.log`、`data/ledger/update-log.jsonl`；手动 `./update` 重试 | 不要删账本「重来」 |
| 自动更新某一步失败 | 单步失败不阻断其他步骤；重跑即可（幂等、重叠跳过） | 不要用冲突内容覆盖已有快照/账本 |
| 快照校验失败（`SnapshotError`） | `git status` 看是否被本地改动；用 `git checkout -- <路径>` 恢复；或从 git 历史重新检出 | 不要手工改 `*.csv.gz.meta.json` 或无清单重建 |
| 账本 `--check` 报错 | 立即停下，检查是否被手工编辑/重复运行产生不同内容；用 git 恢复被误改的行 | 不要直接删行、改 `record_id` 或覆盖文件 |
| 定时任务不触发 | 看 `~/Library/LaunchAgents/com.investment-system.forward-update.plist` 与日志；重新执行安装脚本 | 不要用 `pkill -f` 之类宽匹配杀进程 |
| 磁盘紧张 | 可安全删除 git 忽略缓存：`data/cache/`（保留 `.gitkeep`）、`data/policy-trial/cache/`、`data/policy-trial/logs/`、`.pytest_cache/`、`__pycache__/`；**不要删 `data/snapshots/`、`data/*/snapshot-*`、账本、政策** | 不要删 `.venv`/`.git`，不要删历史快照 |
| 需要回滚代码 | `git log` 找到上一签收提交，`git revert` 或 `git checkout` 到干净状态 | 不要 `git reset --hard` 抹掉别人提交；不 amend 已推送历史 |
| 需要恢复数据文件 | `git checkout -- <路径>`；历史快照与账本都在 git 里 | 不要从旧项目 `../valuation/` 读取或导入 |

## 12. 本地页面（`./web`）

### 12.1 启动与停止

```bash
./web                 # 默认 http://127.0.0.1:8765/；端口被占用时自动换到 8766–8770 或系统分配
./web --no-browser    # 不自动打开浏览器（地址打印在终端）
./web --no-update     # 与 ./ask --no-update 一致：回答前不尝试联网更新
```

- 只监听 `127.0.0.1`（服务端硬性拒绝其它地址），不访问外网、不上传数据；**关闭终端即停止**。
- 只用 Python 标准库 `http.server`，**没有新增依赖**；不写任何缓存文件。
- 页面与 `./ask` 共用一个 `AskService`：卡片文字、数字、账本写入规则完全相同；
  页面提问的默认分析日与 CLI 一样走 `engine/clock.py`（`INVESTMENT_SYSTEM_TODAY` 仅测试/复现用）。

### 12.2 页面六个部分

| 部分 | 内容 |
|---|---|
| 提问 | 与 `./ask` 相同的输入框；卡片按结论、类型标签、三档价值、买点线、距买点线排版；可展开「详细」（等同 `--detail`） |
| 买点总览 | 候选买点与「离买点最近」排行，按类型分组，可按池/行业/所有制筛选；表内「合理价」「现价/合理价」可排序 |
| 三个池 | 三池表格，可搜索、排序、筛选行业/所有制/周期；点公司打开卡片与成绩单（未通过条件） |
| 指数 | 四只指数的位置说明 + 近 5 年 PE 分位走势（与卡片同一 60 个月窗口规则，来自已提交序列） |
| 账本 | 正式结论历史，按公司查，显示改判记录；任一条可点「复算」（等同 `--recompute`） |
| 数据状态 | 行情日期、上次自动更新时间与结果、下一次复核日期 |

### 12.3 出错与守护

- 页面打不开：先看终端是否还在运行、地址是否被端口占用换过；用 `--no-browser` 时地址会打印出来。
- 提问报错：页面会显示错误类型与原因，与 `./ask` 一致；不会编造答案。
- 一致性守护：`tests/test_web.py` 覆盖「问题集 67 条页面结果与 `./ask` 逐项一致」「10 条代表性
  问题的页面卡片与 CLI 逐字节一致」「复算按钮与 `--recompute` 相同」「页面写账本与 `ask` 同规则」。
- 页面只做排版：`engine/web/app.py` 只调用 `AskService` 与 `engine.repro.recompute`，不另算估值。
